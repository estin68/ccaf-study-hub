CCA-F Cheat Sheet

Exam-day rapid recall guide. Memorize these must-know facts, then take a practice bank and mark your score. Verify against the official Anthropic Exam Guide before sitting.

1 · Models & Capabilities

Model tiers
  • Opus = most capable, slowest, priciest
  • Sonnet = balanced default
  • Haiku = fastest/cheapest, high-volume light tasks
  • Tier = trade-off of capability ↔ speed ↔ cost
Context vs. output
  • Context window = total request token capacity (working memory)
  • max_tokens = cap on ONE response's output length
  • ~1M-token windows on flagship models
Model IDs
  • Dated (e.g. claude-3-5-sonnet-20241022) = pinned snapshot → deterministic
  • Alias (e.g. claude-sonnet-5) = tracks latest stable in tier → auto-upgrade
  • Vision: accept images & PDFs; source = base64 / URL / file_id; put images before text

2 · LLM Core Concepts

Tokens & sampling
  • ~0.75 token ≈ 1 English word → ~1000 tokens ≈ 750 words
  • Low temperature (0–0.3) = deterministic, best for JSON
  • top-p = most-probable-token subset by cumulative prob. mass
  • Streaming = lower perceived latency (deltas)
Why models hallucinate
  • LLMs pick the most-likely next token — no "truth" table
  • Thin/ambiguous context → plausible-but-false continuations
  • Fix = grounding (RAG) + clear evidence + verification

3 · Prompt Engineering

Structure
  • System = instructions/guards (keep untrusted data OUT)
  • User = the actual data/back-and-forth
  • Few-shot = 1–3 example pairs to teach format
  • XML tags = delimiters separating data from instructions
  • Role prompt e.g. "You are a senior..."
Reliable JSON
  • Ask: "return ONLY a JSON object matching this schema"
  • Provide exact fields + types
  • Combine with low temperature → deterministic

4 · Developer Platform

Messages API — REQUIRED
  • model + max_tokens + messages
  • Everything else (system/tools/temp) optional
  • Access: Anthropic API, AWS Bedrock, Google Vertex AI
Cost & latency levers
  • Cheaper tier · smaller prompt token count · prompt caching · Batch API (~50% off, async/offline)
  • RPM/TPM = requests/tokens per minute (quota, not model property)

HTTP Error Codes

400 bad/malformed request (or spend cap) 401 auth — bad API key 402 billing problem 403 permission denied 404 not found 429 rate limit → back off + honor retry-after 500 server error 529 overloaded → exponential backoff

5 · Tool Use, MCP & Agents

Tool loop
  • Model returns tool_use (name + JSON args)
  • YOUR app runs it, returns tool_result
  • Client tools = you define & execute
  • Server tools = Anthropic runs (e.g. web_search)
  • Good description + schema → better tool calls
MCP
  • Server = exposes tools/capabilities/resources
  • Client = bridges model to servers, routes calls

6 · RAG & Context Engineering

Pipeline
  • Embed docs → vectors
  • Vector search finds semantically relevant chunks
  • Inject chunk into prompt → model answers from it (no retraining)
  • Grounding rule: "say when not in context"
  • The retrieval-quality ceiling governs answer quality

7 · Safety, Guardrails & Deployment

Constitutional AI
  • Train on a written "constitution" of principles + feedback
  • Goal: helpful, harmless & honest by default
Defense-in-depth
  • Treat all user content as data — keep out of system prompt
  • Delimit data from instructions (XML)
  • App guardrails: validate actions, least privilege, moderate, monitor
  • Deploy: Anthropic API / AWS Bedrock / Google Vertex AI
